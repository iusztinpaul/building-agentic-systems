# MCP Server for GraphRAG Unified Memory

## Context

Build an MCP server on top of the existing GraphRAG unified memory to let agents query the knowledge graph. The key design choice: instead of hardcoding MongoDB queries, an LLM dynamically translates natural language into MongoDB aggregation pipelines. This gives agents flexible, expressive access to the knowledge graph.

The MCP layer is thin (under `src/twin/mcp/`), delegating all business logic to `memory/query/` and `entities/`.

## Step 2: NL-to-MongoDB Business Logic

**File:** `src/twin/memory/query/nl_query.py`

This is the core business logic — lives in `memory/query/` alongside `core.py`.

### Two Query Modes

The NL tool supports two modes, chosen by the LLM based on the query:

1. **Hybrid search (vector + text):** The LLM generates text search keywords, graph traversals, and filters. For vector search, it uses a `$vectorSearch` stage with `"queryVector": "__EMBED__"` placeholder and a `"queryText"` field. The system replaces the placeholder with the actual embedding computed from `queryText`.

2. **Text-only search:** Full NL-to-MongoDB without vector search. Uses `$text`, `$match`, `$graphLookup`, filters, aggregations — all generated by the LLM.

### System Prompt

Built dynamically from existing ontology registries (`ontology.py`) so it stays in sync:

- Collection schema: `knowledge_graph` (nodes and edges in one collection)
- Node document structure: `_id` format (`"type:name"`), `kind="node"`, `type`, `name`, `properties`, `embedding`
- Edge document structure: `_id` (dict), `kind="edge"`, `source_node_id`, `target_node_id`, `type`
- All `NodeType` and `EdgeType` values (from enums)
- Property schemas per node type (from `NODE_PROPERTIES` registry)
- Edge constraints (from `EDGE_CONSTRAINTS` registry)
- Available indexes: text index on `(name, properties.content, properties.aliases)`, vector index on `embedding`
- Placeholder instruction: for vector search, use `"queryVector": "__EMBED__"` with `"queryText": "<text>"` 
- Output format: JSON array of aggregation pipeline stages
- Safety rules: never use write operations

### Key Functions

```python
def build_nl_query_system_prompt() -> str:
    """Build the system prompt dynamically from ontology registries."""

async def nl_to_pipeline(
    llm: BaseLLM,
    query: str,
    *,
    embedding_model: BaseEmbeddingModel | None = None,
) -> list[dict[str, Any]]:
    """Translate NL query to MongoDB pipeline via LLM.
    
    If pipeline contains $vectorSearch with __EMBED__ placeholder,
    computes the embedding and replaces the placeholder.
    """

def validate_pipeline(pipeline: list[dict[str, Any]]) -> list[dict[str, Any]]:
    """Validate pipeline is read-only and safe. Raises PipelineValidationError."""

async def execute_nl_query(
    client: AsyncMongoClient,
    database: str,
    query: str,
    llm: BaseLLM,
    embedding_model: BaseEmbeddingModel,
    *,
    max_retries: int | None = None,
) -> list[dict[str, Any]]:
    """End-to-end: NL -> pipeline -> validate -> execute -> results.
    
    On failure, feeds error back to LLM for self-correction (up to max_retries).
    Returns raw MongoDB documents (list of dicts).
    """
```

### Safety: `validate_pipeline`

**Allowlisted stages:** `$vectorSearch`, `$match`, `$project`, `$sort`, `$limit`, `$skip`, `$count`, `$group`, `$unwind`, `$lookup`, `$graphLookup`, `$addFields`, `$facet`, `$sample`, `$sortByCount`, `$bucket`, `$bucketAuto`, `$redact`

**Blocked (everything not allowlisted)**, notably: `$out`, `$merge`, `$delete`, `$drop`, `$where`, `$function`, `$accumulator`

**Additional guards:**
- `$lookup`/`$graphLookup`: verify `from` field equals `"knowledge_graph"` 
- Inject `$limit` if not present (cap at `app_config.mcp.max_results`)
- Strip `embedding` field from results via `$project: {embedding: 0}` 
- Set `maxTimeMS` on aggregation (10 seconds)

### Embedding Placeholder Replacement

After LLM generates pipeline, scan for `$vectorSearch` stage. If found with `"queryVector": "__EMBED__"`:
1. Extract `queryText` field
2. Call `embedding_model.embed([query_text])`
3. Replace `"__EMBED__"` with the actual vector
4. Remove the `queryText` helper field

### Error Handling

New exception in `src/twin/models/exceptions.py`:
```python
class PipelineValidationError(ModelError):
    """Raised when an LLM-generated pipeline fails safety validation."""
```

Retry logic: on `PipelineValidationError` or `pymongo.errors.OperationFailure`, feed error message back to LLM: `"The pipeline failed with: {error}. Fix it."` — up to `max_retries` attempts.

## Step 4: MCP Tools

**File:** `src/twin/mcp/tools.py`

### Tool 1: `query_memory` (NL-to-MongoDB)

```python
@mcp.tool
async def query_memory(query: str, ctx: Context) -> str:
    """Query the knowledge graph using natural language.
    
    Dynamically translates the query into a MongoDB aggregation pipeline.
    Supports hybrid search (vector + text), text-only search, graph traversals,
    filters, and aggregations.
    """
```

Delegates to `execute_nl_query()` from `nl_query.py`. Serializes results to JSON string.

### Tool 2: `search_memory` (Structured fallback)

```python
@mcp.tool
async def search_memory(query: str, ctx: Context, top_k: int = 10, max_hops: int = 3) -> str:
    """Search the knowledge graph using semantic + text search with graph expansion.
    
    Uses vector similarity + text search with RRF fusion to find seed nodes,
    then expands the graph around them. Reliable fallback for semantic similarity.
    """
```

Delegates to existing `query_memory()` from `memory/query/core.py`. Returns `QueryResult` serialized.

### Serialization

Use `bson.json_util.dumps` (from pymongo, already a dependency) for `ObjectId`/`datetime` handling. Strip `embedding` fields from results to reduce payload.
