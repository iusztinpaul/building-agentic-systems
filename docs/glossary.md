# Glossary

The canonical vocabulary for **Tree**. When code, tests, docs, specs, or
conversation use a domain concept, use the term as it appears here — one name
per concept. Seeded from the data-pipeline sharding work; grows as the codebase
does. (Discipline borrowed from DDD's *ubiquitous language*.)

| Term | Definition | Notes |
|---|---|---|
| **Backfill sources** (`sources/backfill.yaml`) | The one-shot ingest set: `substack_article`, `huggingface_dataset`, `youtube_video`, and plain `web` URLs — sources that do not gain new items after first ingest. | Loaded by a manual/default `run-data-pipeline` run (together with **Listen sources**); never by the nightly cron. The only place a `huggingface_dataset` may be defined (the `--uri` mode rejects it). |
| **Batch** | The unit a single ETL-phase task operates over: a streaming chunk of `batch_size` rows (HuggingFace), or one feed's entries, or the whole handed-in URL list. Processed concurrently under `asyncio.Semaphore(concurrency)` / a bulk fetch. | In-worker, in-process unit. The grain of an **ETL-phase task** (one task per phase, per batch — NOT per row). Distinct from a **Window** (cross-run, one per Worker) — don't call a Window a "batch". |
| **Child chunk** | A small (default 256 tokens) `type: chunk, subtype: child` row in the `memory` collection, produced by splitting a **Parent chunk** with the same chunking strategy; `parent_id` = the parent row's `_id`, `chunk_index` = position among siblings. The ONLY chunk level that carries an `embedding`. Since `embedding-clusters-viz` it also carries two top-level fields written by a **Clustering run**: `cluster_id: int \| None` (`-1` = noise, `None` = never clustered) and `viz: {x, y, run_id} \| None` (its **Embedding map** coordinates). | Embedded on its **Contextual header** text, NOT on its stored `properties.content`. Hybrid search runs over children; results are reported as their parents (**Parent-document retrieval**). Written identically in both **Memory modes**; in `graphrag` it additionally gets `part_of`→parent and `next` edges. Distinct from a **Parent chunk** (never embedded). Only child rows may carry `cluster_id` / `viz` (validator). |
| **Clean step** | The FIRST memory-pipeline stage: `tree.memory.rag.cleaning.clean_text`, a deterministic, pure function (stdlib only — no Prefect, DB, config or pipeline imports) that strips control chars/surrogates, normalises markdown, drops boilerplate lines (cookie banners, nav residue, lines repeated 3+ times) and collapses intra-line whitespace. | Pure so a future fine-tuning pipeline imports the SAME function (no train/serve drift). Idempotent, so Prefect `INPUTS` caching downstream stays valid. Good: dropping a standalone `Subscribe` line. Bad: touching a paragraph that merely contains "subscribe". Distinct from the data pipeline's HTML→markdown conversion. |
| **Clustering run** | One execution of the `memory_clustering` sub-flow (`memory-clustering-etl`, phase 4 of `offline_pipeline`, on when `run_clustering=True`) for ONE user: load every embedded **Child chunk** → UMAP to 5-d → HDBSCAN → a separate UMAP to 2-D → one LLM summary per cluster → write. Identified by `run_id` (the Prefect flow-run id), carried on every **Memory cluster** row and on every child's `viz.run_id`. | LATEST RUN ONLY: a new run deletes the user's previous `memory_clusters` rows and overwrites the chunk fields — there is no run history. Noise (`-1`) is stored on the chunk but never gets a cluster row. A chunk whose `cluster_id is None` or whose `viz.run_id` differs from the latest run is *unclustered / stale* and triggers the surfaces' warning line. Skipped (previous run kept) when fewer than `min_cluster_size` embedded children exist. Mode-orthogonal — identical in `rag` and `graphrag`; writes NO graph rows, NO edges. Off by default; the switch is the flow parameter, NOT a YAML key. |
| **Contextual header** | The document `title` plus the parent's `heading_path` (joined with ` > `) prefixed to a **Child chunk**'s content to form its embedding text: `"{title}\n{h1 > h2}\n\n{content}"`. Built by `tree.memory.rag.embedding.child_embedding_text`. | Embedding-text only — `properties.content` stays the raw child text. Both inputs are denormalised onto the child row (`properties.title`, `properties.heading_path`) so the indexing backfill rebuilds the identical text without a join. Empty title/headings → plain content. |
| **Coordinator** | The single Prefect flow per pipeline that reads config, groups/partitions the work, and dispatches **Worker** runs at **depth-1** (never recursively). Formerly "Orchestrator" — renamed to avoid collision with Prefect, the pipeline *orchestrator*. | One per pipeline (e.g. `data_etl_coordinator`). Since `free-tier-deployments` (#098–#102) a Coordinator is a FLOW but no longer a **Deployment**: both run as inline subflows of the `offline-pipeline` run, which holds the one admission slot while they await their Workers. Still dispatches Worker runs at depth-1 via `run_deployment`. The memory Coordinator NO LONGER runs indexing after its shards — indexing is its own **Offline phase** (ADR-007). Distinct from a **Worker**, and from Prefect (the orchestrator that runs all Deployments). |
| **Data Pipeline** | The ETL half that gathers raw source data and normalizes it into the `documents` collection. | Produces **Document**s only — there is NO index step. Distinct from the **Memory Pipeline**. |
| **Dedicated endpoint** | A Modal-managed model server created with `modal endpoint create --name <endpoint_name> --model <model> --routing-region eu-west [--custom-hf-repo <repo_id> --custom-hf-revision <revision>]` (dashboard: Endpoints -> Create new endpoint -> "Deploy a dedicated endpoint"): Modal resolves the model, picks a serving recipe and generates the app's `serve.py` — no code of ours. Available ONLY for the models in Modal's endpoint catalog (44 on 2026-09-20: 2 embedding models — `Qwen/Qwen3-Embedding-0.6B`, `-8B` — and 42 chat LLMs) and for SAME-ARCHITECTURE fine-tunes of them passed as custom weights. | The `endpoint` **Serving path** — always tried FIRST by the deploy driver (ADR-009 §2); never configured. Modal is the oracle: there is no "can you serve X" API, so the driver runs the create and reads the refusal — `… is not available for dedicated Endpoints` (followed by Modal's model list) or `… is not a servable checkpoint of base model …`; nothing is created on a refusal. Scales to zero by default, billed by GPU-second; **Proxy token** auth on by default; OpenAI-compatible `/v1/embeddings` or `/v1/chat/completions`. Modal, not us, picks GPU, engine, engine version, flags and the weights snapshot (the entry's `revision` and App fields are not used); min/max/buffer containers are dashboard-only. Runs as the Modal app `ep-<endpoint_name>` with ONE server class `Server` (seen in all four generated `serve.py` files; confirmed for our names in `tasks/141`), which is why our App scripts copy that shape. OURS are always named `tree-<model>` (app `ep-tree-<model>`); one an operator made by hand in the dashboard is `ep-<model>`, is NOT ours, and is never called, deployed over or stopped by our targets (ADR-009 §3). Its Source-view `serve.py` is the template our App scripts follow. Stopped with `modal endpoint stop -y <endpoint_name>`, listed with `modal endpoint list`. Distinct from a Prefect **Deployment** and from Modal's shared (non-dedicated) endpoints. |
| **Deployment** | A Prefect flow registered with the server / work pool and triggerable by name. | Capped at 5 on the Prefect free tier; we register 5 (`orchestrator.py::_DEPLOYMENT_SPECS`) — the cap is exactly spent, NO slot spare. Distinct from a **Worker** (a *run* of a Deployment) and from an **ETL-phase task** (an in-run unit, not a Deployment). A "Docker" / "machine" is not a Deployment. The clustering phase added NO deployment (`memory-clustering-etl` is an inline subflow like indexing). |
| **Document** | A normalized source record in the `documents` collection; the Data Pipeline's output unit. | Deduped on `(user_id, source_uri)`. Distinct from the `document` ROW in the `memory` collection (the metadata root of a chunk hierarchy) and from a Node. |
| **Embedding map** | The 2-D scatter of a user's **Child chunk**s from the latest **Clustering run**, drawn by the **Graph renderer** with FIXED coordinates (`viz.x/y`, ForceAtlas2 skipped), coloured per **Memory cluster** from a 20-colour categorical palette (noise mid-grey), with a legend (label + size), an optional convex-hull overlay per cluster, and a tooltip (cluster label, document title, heading path, snippet). Built by `tree.memory.visualize.embeddings.to_embedding_map_payload` from an `EmbeddingMap`. | Surfaces: MCP tool `visualize_memory_embeddings(hulls, as_html_file)` in BOTH modes and `make memory-visualize-embeddings`; both READ stored coordinates, never compute. Warning contract: the output starts with `"N of M chunks have no cluster assignment (or a stale one) — run make memory-run-clustering-pipeline"` when any child is unclustered/stale (those points are omitted and counted in the legend); with no run at all the surfaces return an explanatory message, never an empty map. Same dual delivery as the graph (inline MCP App iframe, else `.tree/graphs/embedding-map-<stamp>.html` + `graphs://`). Distinct from a **Graph payload** (nodes + edges, force layout) — the map has no edges. |
| **Embedding reset** | `make memory-reset-embeddings` → `tree.memory.rag.indexing.reset_embeddings`: for ONE user, sets `embedding = []` on every embedded backfill-eligible row (**Child chunk**s + LLM-extractable entity nodes) and clears the children's `cluster_id` / `viz`, so the indexing **Offline phase** re-embeds them with the current `models.search_embedding`. Dry run unless `CONFIRM=yes`; idempotent. | The migration for ANY change that makes persisted vectors incomparable — a new embedding model (voyage-3.5 → voyage-4) or a new **Embedding role** rule — because rows carry NO model stamp (ADR-009 §7). Sequence: reset → `make memory-run-indexing-pipeline` → `make memory-run-clustering-pipeline`. Resets only rows the backfill filter refills (never a vector it cannot rebuild). Between reset and indexing, search degrades to the text leg. Leaves `memory_clusters` rows for the next **Clustering run** to replace; the cleared `viz` is what makes the **Embedding map** warn instead of silently drawing old-space coordinates. NOT a vector-index rebuild (dimensions unchanged). |
| **Embedding role** | The optional `input_type: "query" \| "document" \| None` argument of `BaseEmbeddingModel.embed` (`tree.models.base.EmbeddingRole`), telling an asymmetric model which side of retrieval a text is on. Rule: every PERSISTED vector (child chunks, entity nodes, preference/fact statements) is `document`; every USER-QUESTION vector (`rag/search.py`, `graph/nl_query.py`) is `query`; the transient resolution embedding (name-vs-name, never stored) is `None`. | The rule is FORCED, not chosen: dedup compares the very vector it then persists ("dedup vector == persisted vector, computed once", `pipeline.py`), so that vector must be `document`. Provider mapping: Voyage → API `input_type`; Gemini → `task_type` `RETRIEVAL_QUERY` / `RETRIEVAL_DOCUMENT`; sentence-transformers → `prompt_name` only if the model defines that prompt; Modal → the **Modal catalog** entry's `query_prompt` / `document_prompt` prepended client-side; mocks ignore it. A provider that cannot honour a role ignores it, never raises. Part of the embed-task cache identity (`voyage:voyage-4:1024:document`). Changing the rule requires an **Embedding reset**. Not a **Memory mode** and not a **Search mode**. |
| **ETL-phase task** | A Prefect `@task` in a batch ETL flow that runs ONE ETL phase (Extract / Transform / enrich / Load) over a whole **Batch** — never per row. Phases that genuinely separate get their own task (a pure dict→Document map is a `transform_batch`; a network re-fetch is an `enrich_batch`); Extract+Transform fuse where a single scrape yields the Document; **Load is ALWAYS its own task**. Per-element isolation lives *inside* the task (`asyncio.gather(return_exceptions=True)`: a bad-data element is logged + skipped, never sinking the batch; a batch-wide infra failure hard-fails the task → Prefect retries the whole batch, safe because Load is idempotent on `(user_id, source_uri)`). | The Prefect-UI run count drops from ~1 task/row to a few per batch (a 1000-doc window worker goes from ~1000 task runs to tens). Operates over a **Batch**; retry grain is the batch (fetch/extract `retries=2`, load `retries=1`, pure transform `retries=0`); per-element transient fetch retries live in the fetch layer. Distinct from a **Worker** (a flow *run*) and a **Deployment**. |
| **Graph payload** | The renderer-agnostic `{nodes, edges}` dict built by `to_graph_payload` (`tree.memory.visualize.graph`) from a `QueryResult`: every edge endpoint guaranteed present as a node, each node/edge carrying display name, colour, and a curated `meta` subset. | The SINGLE contract between the query layer and every graph surface — the MCP App iframe (`audience=["user"]` content block + `structured_content`), the self-contained HTML file, and the CLI all consume the same payload. Distinct from a raw `QueryResult` (Mongo rows) and from the rendered HTML. graphrag-only surfaces: `visualize_memory_graph`, `memory_dashboard`, `query_memory` and `search_memory(visualize=True)` are registered only when **Memory mode** is `graphrag` (no edges exist in `rag`). The **Embedding map** reuses the same `{nodes, edges}` shape plus optional keys (`layout: "fixed"`, `legend`, `hulls`, `warning`) understood by the one template; a payload without those keys renders exactly as before. |
| **Graph renderer** | The one browser-side stack that draws a **Graph payload**: graphology (model) + graphology-layout-forceatlas2 (layout) + Sigma.js (WebGL), pinned ESM from jsdelivr, embedded in the shared HTML templates in `tree.memory.visualize.graph` (a NEUTRAL package — `graph/` may import it, `rag/` never does). | The ONLY renderer since `single-graph-renderer` (ADR-005) — the Python pyvis/networkx renderer is deleted; never reintroduce a second stack. Delivery is dual and uniform across ALL graph-capable MCP tools (`visualize_memory_graph`, `query_memory`, `search_memory`) via the one `_graph_tool_result` helper in `tree.mcp.viz_app` (mode-neutral; the graphrag-only tools live in `tree.mcp.graph_tools`): inline MCP App iframe when the client supports the UI extension, else a self-contained file under `.tree/graphs/<query-slug>-<UTC-stamp>.html` + a `graphs://<name>` resource. Needs network to draw (CDN — accepted offline regression, ADR-005). graphrag-only surfaces: `visualize_memory_graph`, `memory_dashboard`, `query_memory` and `search_memory(visualize=True)` are registered only when **Memory mode** is `graphrag` (no edges exist in `rag`). Also draws the **Embedding map** (fixed coordinates, ForceAtlas2 skipped, hull overlay) — `visualize_memory_embeddings` is registered in BOTH modes. |
| **Ingest error** (`Document.ingest_error`) | A normalized failure marker (`"<code>: <message>"`, e.g. `no_transcript: …`, `invalid_url: …`) persisted on a **Document** whose ingestion produced no content (`content=None`). | Written only by the YouTube path (feature `brightdata-youtube-transcripts`). Excluded from extraction by the existing `content != None` filter. An errored row is REPLACEABLE on a later run, exactly like `SourceType.LATENT` — no attempt cap. Never a raw exception dump. |
| **Ingest receipt** | The answer of every ingest tool (`ingest_url`, `ingest_file`, `ingest_conversation`) and of `tree.online.dispatch_online_pipeline`: `{source_uri, duplicate, document_id, flow_run_id, status}` (+ the tool's `url` / `file_path`). `source_uri` is the **Document**'s natural key, derived by ONE helper per leaf (`source_uri_for`); `duplicate` is the verdict KNOWN AT SUBMIT TIME from a pre-flight `(user_id, source_uri)` lookup. | `document_id` is set iff `duplicate` (only then is the id known); `flow_run_id` is set iff a run was dispatched; a duplicate dispatches nothing (`status: "duplicate"`). A `LATENT` row is NOT a duplicate (the leaf upgrades it). Two concurrent submits may both read `duplicate: false` — the worker still dedupes. Retry with `SOURCE_URIS=<uri>` or `DOC_IDS=<id>`. `Document._id` stays a random ObjectId. |
| **Listen sources** (`sources/listen.yaml`) | The repeatedly-polled feed set: `substack_rss` and `youtube_rss`. | The nightly cron (`0 3 * * *` UTC, on the `offline-pipeline` **Deployment** since `free-tier-deployments`) loads ONLY this file (`source_files=["sources/listen.yaml"]`), fanned across all active users — and continues through the extraction and indexing **Offline phase**s (clustering stays off) so nightly documents never sit PENDING. |
| **Memory cluster** | One HDBSCAN cluster of a user's **Child chunk** embeddings, persisted as a row of the `memory_clusters` collection (Beanie `MemoryCluster`, `tree.entities.clusters`): `user_id`, `run_id`, `cluster_id` (≥ 0), LLM-written `label` (≤ 6 words), `summary` (≤ 100 words), `keywords` (3–5), `size`, `sample_chunk_ids` (the ≤ 20 chunks the LLM saw: 10 nearest the centroid in the ORIGINAL embedding space + 10 seeded random), `centroid {x, y}` in **Embedding map** space, `created_at`. `_id = "{user_id}:cluster:{cluster_id}"`. | A SEPARATE collection, not a `memory` node: clusters are derived, per-run, mode-orthogonal artefacts with a different lifecycle (replaced wholesale each run). Membership lives on the chunk (`MemoryEntry.cluster_id`), not on the cluster. A failed summary yields `label = "Cluster {id}"`, empty summary — the run never fails on one cluster. Distinct from a POLE+O node, from a **Shard**, and from noise (`-1`, no row). |
| **`memory` collection** | The ONE MongoDB collection (Beanie `MemoryEntry`, `tree.entities.memory.MEMORY_COLLECTION`) holding every memory row in both **Memory modes**: `document` / `chunk` (**Parent chunk**, **Child chunk**) rows in `rag`; those plus entity nodes and `kind: edge` rows in `graphrag`. Renamed from `knowledge_graph` (ADR-001 §1, superseded on the name by ADR-006). | Polymorphic `kind: node \| edge` rows with deterministic `_id`s (unchanged); ONE ODM class — no `RagEntry`/`KnowledgeGraphEntry` hierarchy (ADR-006 §1). `RAG_NODE_TYPES = {document, chunk}` is the explicit closed set of node types the RAG layer writes. In `rag` it contains NO edge rows — the chunk→parent→document relation is the `parent_id` field. One vector index (`embedding`; filter paths `user_id, kind, type, subtype, merged_into`) + one text index. Never say "knowledge_graph collection" for new code. |
| **Memory mode** | The `memory.mode: rag \| graphrag` YAML enum (`AppConfig.memory`, override `TREE_MEMORY__MODE`) that the memory pipeline, retrieval and MCP tool registration branch on. `rag` = **Clean step** → two-level chunking → embed children → load rows; hybrid **Parent-document retrieval**. `graphrag` = the rag stages PLUS structural edges, LLM entity extraction over **Parent chunk**s, resolution, dedup, `mentions`, and graph expansion at retrieval. | Read once at flow entry / server boot; not per request. Default `graphrag`. Both modes start from scratch — NO data migration between them. Same 5 Prefect **Deployment**s in both modes. Clustering and the **Embedding map** are mode-orthogonal (identical in both). |
| **Memory Pipeline** | The ETL half that maps **Document**s into rows of the `memory` collection: in both **Memory mode**s a `document` row, **Parent chunk**s and embedded **Child chunk**s; in `graphrag` additionally entity nodes and edges (part_of, next, mentions, related_to, …). | Distinct from the **Data Pipeline**. Still shards by document-**Shard** (`num_shards`). ONE flow body (`tree.memory.pipeline`) — rag stages always, graph stages only when `memory.mode == graphrag`. Indexing and clustering are sibling **Offline phase**s of `offline_pipeline`, not stages of the extraction flow. |
| **Modal catalog** | The `modal.embedding_models` and `modal.llm_models` lists in `configs/default.yaml` (Pydantic `ModalEmbeddingModelConfig` / `ModalLLMModelConfig`, `tree.config.app_config`): one entry per Hugging Face model that may be served on Modal. It says WHICH model and the facts about it — never HOW it is served (there is no `serving` or `base_model` field; see **Serving path**). Every entry: `repo_id`, `revision`, the App fields `gpu`, `cpu`, `memory_mb`, `max_model_len`, `extra_server_args` (optional, with defaults; read only when the model runs as our App), and the derived `kind` (`embedding` \| `llm` — from WHICH LIST the entry lives in, never guessed), `endpoint_name` / `app_name`, namespaced with the fixed project prefix `tree-` (`voyageai/voyage-4-nano` -> `tree-voyage-4-nano` / `ep-tree-voyage-4-nano`; `app_name` at most 63 characters). Embedding entries add `native_dimensions` (the vector width the server returns when NO `dimensions` parameter is sent — measured, never read off `hidden_size`: `voyageai/voyage-4-nano` is 2048 through a 1024->2048 linear head, `Qwen/Qwen3-Embedding-0.6B` is 1024), `matryoshka_dimensions`, `query_prompt`, `document_prompt`; LLM entries add `n_gpus` (SGLang's `tp`) and two optional REQUEST knobs sent only when set — `max_tokens` and `chat_template_kwargs` (e.g. `{enable_thinking: false}` for a thinking model; client-side, so the same on both Serving paths and changed without a redeploy; `chat_request_knobs(entry)` feeds `ModalLLM` and the chat smoke test alike). Read through `tree.models.modal_catalog`. Formerly *Embedding catalog* (renamed when LLMs joined, 2026-09-20). | The SINGLE source for both sides: the deploy driver (`scripts/modal_model.py`, `make memory-deploy-model MODEL=<repo_id>` / `-test` / `-stop` — ONE target family for both kinds) and the clients (`ModalEmbeddingModel`, `ModalLLM`) resolve the same entry by `repo_id`, so they cannot disagree on app name, dimensions or prompts. A `repo_id` and a derived app name are unique ACROSS both lists; unknown id -> a `ModelError` listing both groups. Seeds: embeddings `Qwen/Qwen3-Embedding-0.6B`, `voyageai/voyage-4-nano`; LLMs `Qwen/Qwen3.5-0.8B`, `LiquidAI/LFM2.5-350M`. The embedding client never sends an OpenAI `dimensions` parameter: it requests the native width, asserts every response is `native_dimensions` wide (`ExtractionError` otherwise — the catalog can be wrong about a model, and once was), then truncates + L2-renormalises client-side to a listed size, identically on both Serving paths (Modal's own 0.6B and 8B recipes disagree on `is_matryoshka`). ONE Modal app per model. The prefix is the ownership mark: the driver refuses to deploy or stop any name without it, and before a deploy it lists the workspace and refuses (exit 3, `FORCE=yes` overrides) a name that is live as something the command would not merely update; `DRY_RUN=yes` logs the redacted command and starts no `modal` process. Also holds `modal.warmup_deadline_s` and `modal.request_timeout_s` (see **Warm gate**) and the per-ENGINE pins (`modal.engines`). Server-arg values must be whitespace-free (compact JSON); the mode / identity / parallelism flags are builder-owned. Distinct from `models.search_embedding` / `models.llm` (WHICH model the memory uses) — the catalog says what CAN be served — and from Modal's own endpoint catalog (what Modal can serve as a **Dedicated endpoint**) (ADR-009). |
| **Offline phase** | One of the FOUR independently switchable blocks of `tree.offline.offline_pipeline`, each a flow parameter with the SAME name pattern: `run_data` (Data Pipeline coordinator), `run_extraction` (one extraction **Coordinator** per user), `run_indexing` (`memory_indexing` once per user), `run_clustering` (one **Clustering run** per user; default `False`, every other phase defaults `True`). Phases run as sequential blocks, each fanned per target user with per-user failure isolation. | The single-step scripts are the phases with the others OFF: `run-data-pipeline` (data), `run-memory-pipeline` (extraction + indexing), `run-indexing-pipeline` (indexing), `run-clustering-pipeline` (clustering); all dispatch `offline-pipeline` — no script runs a flow in-process. The nightly cron keeps the defaults (data, extraction, indexing; NO clustering). Indexing is a phase, NOT something the extraction Coordinator does (ADR-002 §3's trailing-index rule is superseded by ADR-007). `online_pipeline` is not phased: it keeps its inline single-document indexing. |
| **Parent chunk** | A large (default 4096 tokens) `type: chunk, subtype: parent` row: `parent_id` = the `document` row `_id`, `chunk_index` = position in the document, `properties.heading_path` = the markdown heading stack at its start. NEVER embedded (`embedding: []`). | The unit returned by **Parent-document retrieval** and, in `graphrag`, the unit the LLM extracts entities from (one LLM call per parent — bigger context, fewer calls). Never a search seed. Distinct from a **Child chunk**. |
| **Parent-document retrieval** | Retrieval that hybrid-searches (vector + text, RRF) **Child chunk**s only, groups the fused hits by `parent_id` keeping the best score and the matched children, then returns the distinct **Parent chunk**s ranked by best-child score with their document metadata attached (`tree.memory.rag.retrieval.retrieve_parents` → `RetrievalResult`). | In `rag` this IS `search_memory`. In `graphrag` it resolves the chunk seeds; graph expansion then runs from the parent ids ∪ entity seed ids (children are never expansion seeds). Grouping happens in Python after RRF (fusion is client-side). Fetches `top_k × 4` children to fill `top_k` parents. |
| **Platform** | A source family used as the data Coordinator's grouping key: `{SubstackRss, SubstackArticle}→substack`, `{YouTubeRss, YouTubeVideo}→youtube`, `Web→custom`, `HuggingFace→huggingface`. | One **Worker** run per Platform. Distinct from a **Source variant** (many variants → one Platform). |
| **Pre-warm** | `tree.models.get_model.prewarm_models(*models)`: before the first document of a run that fans out over Modal-backed models, warm every DISTINCT Modal app concurrently through each model's **Warm gate**. Duck-typed on `ensure_warm` / `warm_key`, so Voyage, Gemini, sentence-transformers and the mock make it a no-op. | Called at the top of the extraction worker (after the zero-documents guard — an empty run never wakes a GPU), in dream consolidation and before the cluster-summary fan-out. A dead server fails the run with ZERO documents attempted instead of N failed documents; the first failure cancels its siblings explicitly (a 403 on one server does not wait out the other's 600 s). A plain awaited helper, NOT a Prefect task (a cached "warm" is the t0 fallacy; retries would multiply the deadline). Cluster summaries stay fail-open (ADR-007 §4): a dead LLM there is one WARNING and the fallback labels. NOT used by the indexing backfill, the MCP server's `app_lifespan` or scripts — the **Warm gate** warms at use there (a process that lives for hours must not boot a GPU that idles out in 5 minutes). Needed here more than elsewhere because model objects are built per Prefect task: the pre-warm shares the warm SERVER, not the instance (ADR-009 §11). |
| **Proxy token** | A Modal workspace credential pair — `MODAL_PROXY_TOKEN_ID` (`wk-…`) + `MODAL_PROXY_TOKEN_SECRET` (`ws-…`) in `.env` — that Modal's edge checks before a request reaches a **Dedicated endpoint** (required by default) or one of our Apps (deployed with the literal `unauthenticated=False`). Sent as `Authorization: Bearer <id>.<secret>`, so the `AsyncOpenAI` clients use the joined value as their `api_key` and the **Warm gate**'s `/health` poll sends the same header. | The ONLY auth on Modal-hosted servers — embeddings and LLMs — since ADR-009 §4, identical on both **Serving path**s; replaces the engine-level `--api-key` / `MODAL_EMBEDDING_API_KEY` and its `vllm-embedding-api-key` Modal secret (all retired). One pair covers every app in the workspace — nothing per model. Missing/empty -> `ModelError` at model construction; a 401/403 from `/health` is a configuration error — the poll fails after ONE attempt, it is never waited out; both smoke tests assert a 401 WITHOUT the header. Never logged. Credentials, so they live in `.env.example` (unlike YAML knobs). Distinct from the Modal CLI token (`modal token new`) that authorises `modal deploy` / `modal endpoint create`, and from the optional `HF_TOKEN` (a weight-download credential). |
