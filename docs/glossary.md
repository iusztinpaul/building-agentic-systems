# Glossary

The canonical vocabulary for **Tree**. When code, tests, docs, specs, or
conversation use a domain concept, use the term as it appears here — one name
per concept. Seeded from the data-pipeline sharding work; grows as the codebase
does. (Discipline borrowed from DDD's *ubiquitous language*.)

| Term | Definition | Notes |
|---|---|---|
| **Backfill sources** (`sources/backfill.yaml`) | The one-shot ingest set: `substack_article`, `huggingface_dataset`, `youtube_video`, and plain `web` URLs — sources that do not gain new items after first ingest. | Loaded by a manual/default `run-data-pipeline` run (together with **Listen sources**); never by the nightly cron. The only place a `huggingface_dataset` may be defined (the `--uri` mode rejects it). |
| **Batch** | The unit a single ETL-phase task operates over: a streaming chunk of `batch_size` rows (HuggingFace), or one feed's entries, or the whole handed-in URL list. Processed concurrently under `asyncio.Semaphore(concurrency)` / a bulk fetch. | In-worker, in-process unit. The grain of an **ETL-phase task** (one task per phase, per batch — NOT per row). Distinct from a **Window** (cross-run, one per Worker) — don't call a Window a "batch". |
| **Child chunk** | A small (default 256 tokens) `type: chunk, subtype: child` row in the `memory` collection, produced by splitting a **Parent chunk** with the same chunking strategy; `parent_id` = the parent row's `_id`, `chunk_index` = position among siblings. The ONLY chunk level that carries an `embedding`. | Embedded on its **Contextual header** text, NOT on its stored `properties.content`. Hybrid search runs over children; results are reported as their parents (**Parent-document retrieval**). Written identically in both **Memory modes**; in `graphrag` it additionally gets `part_of`→parent and `next` edges. Distinct from a **Parent chunk** (never embedded). |
| **Clean step** | The FIRST memory-pipeline stage: `tree.memory.rag.cleaning.clean_text`, a deterministic, pure function (stdlib only — no Prefect, DB, config or pipeline imports) that strips control chars/surrogates, normalises markdown, drops boilerplate lines (cookie banners, nav residue, lines repeated 3+ times) and collapses intra-line whitespace. | Pure so a future fine-tuning pipeline imports the SAME function (no train/serve drift). Idempotent, so Prefect `INPUTS` caching downstream stays valid. Good: dropping a standalone `Subscribe` line. Bad: touching a paragraph that merely contains "subscribe". Distinct from the data pipeline's HTML→markdown conversion. |
| **Contextual header** | The document `title` plus the parent's `heading_path` (joined with ` > `) prefixed to a **Child chunk**'s content to form its embedding text: `"{title}\n{h1 > h2}\n\n{content}"`. Built by `tree.memory.rag.embedding.child_embedding_text`. | Embedding-text only — `properties.content` stays the raw child text. Both inputs are denormalised onto the child row (`properties.title`, `properties.heading_path`) so the indexing backfill rebuilds the identical text without a join. Empty title/headings → plain content. |
| **Coordinator** | The single Prefect flow per pipeline that reads config, groups/partitions the work, and dispatches **Worker** runs at **depth-1** (never recursively). Formerly "Orchestrator" — renamed to avoid collision with Prefect, the pipeline *orchestrator*. | One per pipeline (e.g. `data_etl_coordinator`). Since `free-tier-deployments` (#098–#102) a Coordinator is a FLOW but no longer a **Deployment**: both run as inline subflows of the `offline-pipeline` run, which holds the one admission slot while they await their Workers. Still dispatches Worker runs at depth-1 via `run_deployment`. Distinct from a **Worker**, and from Prefect (the orchestrator that runs all Deployments). |
| **Data Pipeline** | The ETL half that gathers raw source data and normalizes it into the `documents` collection. | Produces **Document**s only — there is NO index step. Distinct from the **Memory Pipeline**. |
| **Deployment** | A Prefect flow registered with the server / work pool and triggerable by name. | Capped at 5 on the Prefect free tier; we register 5 (`orchestrator.py::_DEPLOYMENT_SPECS`) — the cap is exactly spent, NO slot spare. Distinct from a **Worker** (a *run* of a Deployment) and from an **ETL-phase task** (an in-run unit, not a Deployment). A "Docker" / "machine" is not a Deployment. |
| **Document** | A normalized source record in the `documents` collection; the Data Pipeline's output unit. | Deduped on `(user_id, source_uri)`. Distinct from the `document` ROW in the `memory` collection (the metadata root of a chunk hierarchy) and from a Node. |
| **ETL-phase task** | A Prefect `@task` in a batch ETL flow that runs ONE ETL phase (Extract / Transform / enrich / Load) over a whole **Batch** — never per row. Phases that genuinely separate get their own task (a pure dict→Document map is a `transform_batch`; a network re-fetch is an `enrich_batch`); Extract+Transform fuse where a single scrape yields the Document; **Load is ALWAYS its own task**. Per-element isolation lives *inside* the task (`asyncio.gather(return_exceptions=True)`: a bad-data element is logged + skipped, never sinking the batch; a batch-wide infra failure hard-fails the task → Prefect retries the whole batch, safe because Load is idempotent on `(user_id, source_uri)`). | The Prefect-UI run count drops from ~1 task/row to a few per batch (a 1000-doc window worker goes from ~1000 task runs to tens). Operates over a **Batch**; retry grain is the batch (fetch/extract `retries=2`, load `retries=1`, pure transform `retries=0`); per-element transient fetch retries live in the fetch layer. Distinct from a **Worker** (a flow *run*) and a **Deployment**. |
| **Graph payload** | The renderer-agnostic `{nodes, edges}` dict built by `to_graph_payload` (`tree.memory.graph.visualize`) from a `QueryResult`: every edge endpoint guaranteed present as a node, each node/edge carrying display name, colour, and a curated `meta` subset. | The SINGLE contract between the query layer and every graph surface — the MCP App iframe (`audience=["user"]` content block + `structured_content`), the self-contained HTML file, and the CLI all consume the same payload. Distinct from a raw `QueryResult` (Mongo rows) and from the rendered HTML. graphrag-only surfaces: `visualize_memory_graph`, `memory_dashboard`, `query_memory` and `search_memory(visualize=True)` are registered only when **Memory mode** is `graphrag` (no edges exist in `rag`). |
| **Graph renderer** | The one browser-side stack that draws a **Graph payload**: graphology (model) + graphology-layout-forceatlas2 (layout) + Sigma.js (WebGL), pinned ESM from jsdelivr, embedded in the shared HTML templates in `tree.memory.graph.visualize`. | The ONLY renderer since `single-graph-renderer` (ADR-005) — the Python pyvis/networkx renderer is deleted; never reintroduce a second stack. Delivery is dual and uniform across ALL graph-capable MCP tools (`visualize_memory_graph`, `query_memory`, `search_memory`) via the one `_graph_tool_result` helper: inline MCP App iframe when the client supports the UI extension, else a self-contained file under `.tree/graphs/<query-slug>-<UTC-stamp>.html` + a `graphs://<name>` resource. Needs network to draw (CDN — accepted offline regression, ADR-005). graphrag-only surfaces: `visualize_memory_graph`, `memory_dashboard`, `query_memory` and `search_memory(visualize=True)` are registered only when **Memory mode** is `graphrag` (no edges exist in `rag`). |
| **Ingest error** (`Document.ingest_error`) | A normalized failure marker (`"<code>: <message>"`, e.g. `no_transcript: …`, `invalid_url: …`) persisted on a **Document** whose ingestion produced no content (`content=None`). | Written only by the YouTube path (feature `brightdata-youtube-transcripts`). Excluded from extraction by the existing `content != None` filter. An errored row is REPLACEABLE on a later run, exactly like `SourceType.LATENT` — no attempt cap. Never a raw exception dump. |
| **Listen sources** (`sources/listen.yaml`) | The repeatedly-polled feed set: `substack_rss` and `youtube_rss`. | The nightly cron (`0 3 * * *` UTC, on the `offline-pipeline` **Deployment** since `free-tier-deployments`) loads ONLY this file (`source_files=["sources/listen.yaml"]`), fanned across all active users — and continues through extraction and indexing so nightly documents never sit PENDING. |
| **`memory` collection** | The ONE MongoDB collection (Beanie `MemoryEntry`, `tree.entities.memory.MEMORY_COLLECTION`) holding every memory row in both **Memory modes**: `document` / `chunk` (**Parent chunk**, **Child chunk**) rows in `rag`; those plus entity nodes and `kind: edge` rows in `graphrag`. Renamed from `knowledge_graph` (ADR-001 §1, superseded on the name by ADR-006). | Polymorphic `kind: node \| edge` rows with deterministic `_id`s (unchanged); ONE ODM class — no `RagEntry`/`KnowledgeGraphEntry` hierarchy (ADR-006 §1). `RAG_NODE_TYPES = {document, chunk}` is the explicit closed set of node types the RAG layer writes. In `rag` it contains NO edge rows — the chunk→parent→document relation is the `parent_id` field. One vector index (`embedding`; filter paths `user_id, kind, type, subtype, merged_into`) + one text index. Never say "knowledge_graph collection" for new code. |
| **Memory mode** | The `memory.mode: rag \| graphrag` YAML enum (`AppConfig.memory`, override `TREE_MEMORY__MODE`) that the memory pipeline, retrieval and MCP tool registration branch on. `rag` = **Clean step** → two-level chunking → embed children → load rows; hybrid **Parent-document retrieval**. `graphrag` = the rag stages PLUS structural edges, LLM entity extraction over **Parent chunk**s, resolution, dedup, `mentions`, and graph expansion at retrieval. | Read once at flow entry / server boot; not per request. Default `graphrag`. Both modes start from scratch — NO data migration between them. Same 5 Prefect **Deployment**s in both modes. |
| **Memory Pipeline** | The ETL half that maps **Document**s into rows of the `memory` collection: in both **Memory mode**s a `document` row, **Parent chunk**s and embedded **Child chunk**s; in `graphrag` additionally entity nodes and edges (part_of, next, mentions, related_to, …). | Distinct from the **Data Pipeline**. Still shards by document-**Shard** (`num_shards`). ONE flow body (`tree.memory.pipeline`) — rag stages always, graph stages only when `memory.mode == graphrag`. |
| **Parent chunk** | A large (default 4096 tokens) `type: chunk, subtype: parent` row: `parent_id` = the `document` row `_id`, `chunk_index` = position in the document, `properties.heading_path` = the markdown heading stack at its start. NEVER embedded (`embedding: []`). | The unit returned by **Parent-document retrieval** and, in `graphrag`, the unit the LLM extracts entities from (one LLM call per parent — bigger context, fewer calls). Never a search seed. Distinct from a **Child chunk**. |
| **Parent-document retrieval** | Retrieval that hybrid-searches (vector + text, RRF) **Child chunk**s only, groups the fused hits by `parent_id` keeping the best score and the matched children, then returns the distinct **Parent chunk**s ranked by best-child score with their document metadata attached (`tree.memory.rag.retrieval.retrieve_parents` → `RetrievalResult`). | In `rag` this IS `search_memory`. In `graphrag` it resolves the chunk seeds; graph expansion then runs from the parent ids ∪ entity seed ids (children are never expansion seeds). Grouping happens in Python after RRF (fusion is client-side). Fetches `top_k × 4` children to fill `top_k` parents. |
| **Platform** | A source family used as the data Coordinator's grouping key: `{SubstackRss, SubstackArticle}→substack`, `{YouTubeRss, YouTubeVideo}→youtube`, `Web→custom`, `HuggingFace→huggingface`. | One **Worker** run per Platform. Distinct from a **Source variant** (many variants → one Platform). |
| **Shard** | A contiguous, balanced partition of a work list (`tree.sharding._partition_into_shards`). | The Memory Pipeline shards **Document** ids; the Data Pipeline no longer shards by count (it groups by **Platform**). Distinct from a **Window** and a **Batch**. |
| **Source file** | A committed YAML file under repo-root `sources/` listing `SourceEntry`s, loaded dynamically by path (or as the default set) via `tree.config.sources.load_sources`. Two exist: `backfill.yaml` and `listen.yaml`. | The file IS the schedule selector — there is no per-source `scheduled` flag. Read SERVER-SIDE by the coordinator at flow-run time. Distinct from `configs/default.yaml`, which now holds ONLY static memory config (no `sources:`). |
| **Source variant** | A discriminated `SourceEntry` config type (`SubstackRssSource`, `WebSource`, `HuggingFaceDatasetSource`, …). | The fine-grained config unit. Maps up to a **Platform** for grouping. |
| **Thin MCP flow** | The 1-line `@flow` wrapper (`ingest_web_url` / `ingest_substack_article` / `ingest_youtube_video`) around a `_ingest_<x>_one(...)` core function, used ONLY by the MCP **URL router** to ingest a single URL (its own Prefect flow run + Opik trace). | The Data Pipeline's BATCH path does NOT call these wrappers — its **ETL-phase task**s call the `_ingest_<x>_one` core directly, so the per-item sub-flow no longer appears in a batch Worker. Distinct from the batch flow `ingest_<x>_batch` (stable name/signature, called by the worker) and the **URL router** (which routes one URL to the matching thin MCP flow). |
| **Transcript fallback chain** | The uniform order the YouTube ETL tries **Transcript fetcher**s: Bright Data first (one collection per **Batch**), then Gemini over exactly the transcript-less slots (per-video granularity); batch-WIDE triggers (missing Bright Data credentials, trigger rejected, poll timeout) send the whole batch to Gemini. | Same code path on the single-video MCP path and the RSS/offline batch path. Every fallback logs a WARNING stating it consumes Gemini tokens and incurs cost. Credential presence IS the switch — no `enabled` toggle; neither backend configured → up-front RuntimeError. |
| **Transcript fetcher** | A YouTube transcript backend implementing `async fetch_many(list[str]) -> list[FetchedTranscript \| None]`. Two exist: `BrightDataTranscriptFetcher` (primary) and `GeminiTranscriptFetcher` (fallback). | Independent implementations sharing ONLY the `fetch_many` contract — no base class, no inheritance (ADR-004). Constructed inside the Prefect task body, never passed as a task input. Per-slot misses return `None`; batch-wide failures raise. |
| **URL router** | The MCP single-URL dispatcher `ingest_url` (`tree.data.online_pipeline`): routes one URL by domain — static registry → custom-Substack-domain (from config) → generic-web (Bright Data) fallback. | Runtime, per-URL. Used ONLY by the `ingest_url` MCP tool — NOT by the Data Pipeline (the worker dispatches `web` as the last batched **Source variant** via `ingest_web_url_batch`). Distinct from config-load type inference (`_normalize_untyped_entry`, which types untyped URLs once at load) and from the data worker's `isinstance` batched-variant dispatch — three separate mechanisms. |
| **Window** | A disjoint slice `[offset, offset + window_size)` of a HuggingFace dataset, ingested by exactly one **Worker** run. | Cross-run unit, computed by the Coordinator from `num_workers`. Distinct from a **Batch** (in-worker). |
| **Worker** | A single Prefect flow *run* that executes one homogeneous unit of ingestion (a **Platform**'s sources, or one HF **Window**). | A run of the `data-etl-worker` **Deployment** — NOT a separate deployment, Docker, or machine. A Worker NEVER dispatches other Workers (that recursion can deadlock the admission limit). Inside a Worker, a leaf batch ETL flow runs **ETL-phase task**s over its **Batch**(es) — it no longer fans out a per-item sub-flow per Document. |
