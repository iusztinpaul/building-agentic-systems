# Glossary

The canonical vocabulary for **Tree**. When code, tests, docs, specs, or
conversation use a domain concept, use the term as it appears here — one name
per concept. Seeded from the data-pipeline sharding work; grows as the codebase
does. (Discipline borrowed from DDD's *ubiquitous language*.)

| Term | Definition | Notes |
|---|---|---|
| **Backfill sources** (`sources/backfill.yaml`) | The one-shot ingest set: `substack_article`, `huggingface_dataset`, `youtube_video`, and plain `web` URLs — sources that do not gain new items after first ingest. | Loaded by a manual/default `run-data-pipeline-offline` run (together with **Listen sources**); never by the nightly cron. The only place a `huggingface_dataset` may be defined (the `--uri` mode rejects it). |
| **Batch** | The unit a single ETL-phase task operates over: a streaming chunk of `batch_size` rows (HuggingFace), or one feed's entries, or the whole handed-in URL list. Processed concurrently under `asyncio.Semaphore(concurrency)` / a bulk fetch. | In-worker, in-process unit. The grain of an **ETL-phase task** (one task per phase, per batch — NOT per row). Distinct from a **Window** (cross-run, one per Worker) — don't call a Window a "batch". |
| **Data Pipeline** | The ETL half that gathers raw source data and normalizes it into the `documents` collection. | Produces **Document**s only — there is NO index step. Distinct from the **Memory Pipeline**. |
| **Deployment** | A Prefect flow registered with the server / work pool and triggerable by name. | Capped at 5 on the Prefect free tier (`orchestrator.py::_DEPLOYMENT_SPECS`). Distinct from a **Worker** (a *run* of a Deployment) and from an **ETL-phase task** (an in-run unit, not a Deployment). A "Docker" / "machine" is not a Deployment. |
| **Document** | A normalized source record in the `documents` collection; the Data Pipeline's output unit. | Deduped on `(user_id, source_uri)`. Distinct from a **Node** (the Memory Pipeline's unit). |
| **ETL-phase task** | A Prefect `@task` in a batch ETL flow that runs ONE ETL phase (Extract / Transform / enrich / Load) over a whole **Batch** — never per row. Phases that genuinely separate get their own task (a pure dict→Document map is a `transform_batch`; a network re-fetch is an `enrich_batch`); Extract+Transform fuse where a single scrape yields the Document; **Load is ALWAYS its own task**. Per-element isolation lives *inside* the task (`asyncio.gather(return_exceptions=True)`: a bad-data element is logged + skipped, never sinking the batch; a batch-wide infra failure hard-fails the task → Prefect retries the whole batch, safe because Load is idempotent on `(user_id, source_uri)`). | The Prefect-UI run count drops from ~1 task/row to a few per batch (a 1000-doc window worker goes from ~1000 task runs to tens). Replaces the per-row `@task` calls (`extract_document`/`fetch_paper_content`/`load_document` invoked per element). Operates over a **Batch**; retry grain is the batch (fetch/extract `retries=2`, load `retries=1`, pure transform `retries=0`); per-element transient fetch retries live in the fetch layer. Distinct from a **Worker** (a flow *run*) and a **Deployment**. |
| **Listen sources** (`sources/listen.yaml`) | The repeatedly-polled feed set: `substack_rss` and `youtube_rss`. | The nightly `data-etl-orchestrator` cron loads ONLY this file (`source_files=["sources/listen.yaml"]`), fanned across all active users — replacing the retired `scheduled: true` filter. |
| **Memory Pipeline** | The ETL half that maps **Document**s into knowledge-graph Nodes/Edges in the `knowledge_graph` collection. | Distinct from the **Data Pipeline**. Still shards by document-**Shard** (`num_shards`). |
| **Orchestrator** | The single Prefect flow per pipeline that reads config, groups/partitions the work, and dispatches **Worker** runs at **depth-1** (never recursively). | One per pipeline (e.g. `data-etl-orchestrator`). Holds one admission slot while awaiting its Workers. Distinct from a **Worker**. |
| **Platform** | A source family used as the data Orchestrator's grouping key: `{SubstackRss, SubstackArticle}→substack`, `{YouTubeRss, YouTubeVideo}→youtube`, `Web→custom`, `HuggingFace→huggingface`. | One **Worker** run per Platform. Distinct from a **Source variant** (many variants → one Platform). |
| **Shard** | A contiguous, balanced partition of a work list (`tree.sharding._partition_into_shards`). | The Memory Pipeline shards **Document** ids; the Data Pipeline no longer shards by count (it groups by **Platform**). Distinct from a **Window** and a **Batch**. |
| **Source file** | A committed YAML file under repo-root `sources/` listing `SourceEntry`s, loaded dynamically by path (or as the default set) via `tree.config.sources.load_sources`. Two exist: `backfill.yaml` and `listen.yaml`. | The file IS the schedule selector — there is no per-source `scheduled` flag (retired in `sources-config-split`). Read SERVER-SIDE by the orchestrator at flow-run time. Distinct from `configs/default.yaml`, which now holds ONLY static memory config (no `sources:`). |
| **Source variant** | A discriminated `SourceEntry` config type (`SubstackRssSource`, `WebSource`, `HuggingFaceDatasetSource`, …). | The fine-grained config unit. Maps up to a **Platform** for grouping. |
| **Thin MCP flow** | The 1-line `@flow` wrapper (`ingest_web_url` / `ingest_substack_article` / `ingest_youtube_video`) around a `_ingest_<x>_one(...)` core function, used ONLY by the MCP **URL router** to ingest a single URL (its own Prefect flow run + Opik trace). | The Data Pipeline's BATCH path does NOT call these wrappers — its **ETL-phase task**s call the `_ingest_<x>_one` core directly, so the per-item sub-flow no longer appears in a batch Worker. Distinct from the batch flow `ingest_<x>_batch` (stable name/signature, called by the worker) and the **URL router** (which routes one URL to the matching thin MCP flow). |
| **URL router** | The MCP single-URL dispatcher `ingest_url` (`tree.data.online_pipeline`): routes one URL by domain — static registry → custom-Substack-domain (from config) → generic-web (Bright Data) fallback. | Runtime, per-URL. Used ONLY by the `ingest_url` MCP tool — NOT by the Data Pipeline (the worker dispatches `web` as the last batched **Source variant** via `ingest_web_url_batch`). Distinct from config-load type inference (`_normalize_untyped_entry`, which types untyped URLs once at load) and from the data worker's `isinstance` batched-variant dispatch — three separate mechanisms. |
| **Window** | A disjoint slice `[offset, offset + window_size)` of a HuggingFace dataset, ingested by exactly one **Worker** run. | Cross-run unit, computed by the Orchestrator from `num_workers`. Distinct from a **Batch** (in-worker). |
| **Worker** | A single Prefect flow *run* that executes one homogeneous unit of ingestion (a **Platform**'s sources, or one HF **Window**). | A run of the `data-etl-worker` **Deployment** — NOT a separate deployment, Docker, or machine. A Worker NEVER dispatches other Workers (that recursion can deadlock the admission limit). Inside a Worker, a leaf batch ETL flow runs **ETL-phase task**s over its **Batch**(es) — it no longer fans out a per-item sub-flow per Document. |
